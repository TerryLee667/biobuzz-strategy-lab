# 参数敏感性扫描功能（Strategy Showdown 内的 Parameter Sweep）

## Summary（概述）

在 Strategy Showdown 结果页内新增一个「参数敏感性扫描」卡片区：用户选择一个**数值型参数**（机器人滑杆或游戏假设），系统在该参数 min–max 之间自动均匀取 N 个值（含当前设定值），对**每个取值跑一次与现有单次批量测试口径完全相同的完整锦标赛**（每对 `matchesPerPair` 场，批量内**每场对局各自拥有独立 seed**，共数百个不同 seed），策略指标取**该批量全部对局的均值**；然后把每个策略的各项指标（Win%、Avg score、Margin、±SD、Tips、FLOWER pts、RP、4+ tips、7+ tips）画成「指标 = f(参数取值)」的折线图，**每条线 = 一套策略**。用于回答「把某个参数从 A 调到 B，各策略的胜率/得分/TIPS 如何变化」。

## Proposed Changes（改动清单）

### 1) 新增 `src/lib/sim/params.ts` —— 数值参数元数据单一来源

把编辑器与扫描共用的数值参数边界集中一处，避免 min/max 漂移。

```ts
import type { GameSettings, RobotProfile } from "./types";

export interface NumField {
  label: string;
  min: number;
  max: number;
  step: number;
  format: (v: number) => string;
}

/** 键 = 参数字段名。数值与单位逐字照搬现有 profile-editor.tsx。 */
export const PROFILE_FIELDS: Record<
  "widthIn" | "lengthIn" | "heightIn" | "weightLb" | "acceleration" | "intakeWidth" |
  "capacity" | "shotSpeed" | "launchHeightIn" | "driveSpeed" | "intakeTime" | "launchTime" |
  "alignTime" | "flowerTime" | "launchRange" | "pollenAccuracy" | "nectarAccuracy" |
  "flowerAccuracy" | "autoReliability" | "autoSpeed",
  NumField
> = { /* … */ };

export const SETTINGS_FIELDS: Record<
  "tipThreshold" | "tipVariance" | "nectarWeight" | "flowerCapacity" | "defenseEffect" |
  "blockChance" | "tipSpinTime" | "cellHeight" | "ballFriction",
  NumField
> = { /* … */ };
```

- 每个 `NumField` 的 `min/max/step/format/label` **必须与现有 SliderRow 完全一致**（例如 `driveSpeed: {label:"Drive speed", min:1.5, max:10, step:0.25, format:v=>v.toFixed(2)+" ft/s"}`、`pollenAccuracy` 用 `pct`、`intakeTime` 用 `secs`）。
- 不含 `hint`（提示文案留在编辑器中，避免过度耦合）。

### 2) 改 `src/components/sim/profile-editor.tsx` —— 引用共享边界（结构不变，低风险）

- 保持现有 JSX 结构、顺序、hint、Switch/枚举块**完全不动**，仅把每个数值 `SliderRow` 的 `min/max/step/format` 从字面量改为从 `PROFILE_FIELDS.<key>` / `SETTINGS_FIELDS.<key>` 取值（如 `min={PROFILE_FIELDS.driveSpeed.min}`）。
- 目的：消除重复，保证扫描与滑杆的边界永远一致。视觉与行为零变化。

### 3) 新增 `src/lib/sim/sweep.ts` —— 纯逻辑（取值 / 覆盖 / 跑扫描 / 指标注册表）

```ts
import { runTournamentParallel } from "./parallel";
import type { StrategyStats } from "./tournament";
import type { GameSettings, RobotProfile, Strategy } from "./types";

export type SweepTarget = "profile" | "settings";
export interface SweepParam {
  id: string;            // "profile.driveSpeed" | "settings.tipThreshold"
  target: SweepTarget;
  key: string;
  label: string;
  min: number; max: number; step: number;
  format: (v: number) => string;
}
export const SWEEP_PARAMS: SweepParam[];                 // 由 params.ts 生成

export interface Metric {
  id: string; label: string; format: (v: number) => string;
  get: (s: StrategyStats) => number;
}
export const METRICS: Metric[];                          // 见下方 D7

export interface SweepSetup {
  strategies: Strategy[];
  profiles: [RobotProfile, RobotProfile];
  settings: GameSettings;
  matchesPerPair: number;
  seed: number;
}

export function sweepValues(p: SweepParam, count: number, current: number): number[];
export function applyParam(base: SweepSetup, p: SweepParam, value: number): SweepSetup;
export interface SweepPoint { value: number; stats: StrategyStats[] }
export async function runSweep(
  base: SweepSetup, p: SweepParam, values: number[],
  onProgress?: (done: number, total: number) => void,
  shouldCancel?: () => boolean,
): Promise<SweepPoint[] | null>;
```

- `sweepValues`：在 `[min,max]` 上取 `count` 个等距值 → 四舍五入到 `step` 网格 → 去重 → 升序；若 `current` 不在结果中，用最接近的一个替换为 `current`（确保包含当前值）；`count=1` 时返回 `[current]`。
- `applyParam`：`target==="profile"` → `{ ...base, profiles: base.profiles.map(pr => ({ ...pr, [key]: value })) }`（**两台机器人同时覆盖**）；`target==="settings"` → `{ ...base, settings: { ...base.settings, [key]: value } }`；不改动 `base`。
- `runSweep`：遍历 values，逐值调用
  `runTournamentParallel({ ...applyParam(base, p, v), matchesPerPair, seed }, (d,t)=>onProgress?.(i + d/t, values.length), cancelCheck)`；
  即**每个取值 = 一次完整锦标赛批量**（每对 `matchesPerPair` 场，各场 seed = `seed + 序号`，合计数百个独立 seed），`res.stats` 已是对该批量所有对局求出的均值（`avgScore`/`avgRP`/`avgTips`/`p1Rate`… 均为均值，胜率 = `(wins+ties/2)/matches`）——统计口径与现有单次批量测试完全一致。
  收集 `res.stats` 为 `SweepPoint`；`shouldCancel` 为真时立即返回 `null`。**所有取值复用同一 `seed`（默认 1000）**：各取值面对同一 seed 序列，曲线差异纯由参数引起、噪声最小。

## Assumptions & Decisions（决策与假设）

- **D1 边界单一来源**：`params.ts` 提供数值边界，编辑器与扫描共用；编辑器保持现有 JSX 结构，仅替换数字来源。
- **D2 仅数值参数**：布尔/枚举（`drivetrain`、`shooterOnBack`、`shootOnTheMove`、`autoPark`）不参与扫描——折线图需要有序数值 x 轴。
- **D3 作用对象**：扫描机器人参数时**同时作用于两台机器人**（与 Showdown「双方机器人相同以保证公平」一致）；不提供 Robot 1/2 单独扫描。
- **D4 统计口径**：每个参数取值 = **一次与现有单次批量测试完全相同的完整锦标赛**——每对 `matchesPerPair` 场，批量内各场 `seed = 1000 + 序号`（数百个独立 seed），指标取该批量所有对局的均值。所有取值复用**同一 seed 组**（受控对比），使曲线差异纯由参数引起、噪声最小。
- **D5 取值规则**：`[min,max]` 等距 N 点、四舍五入到 step、含当前值；N ∈ {3,5,7,9}，默认 5。
- **D6 性能与场次**：扫描的 `matchesPerPair` **默认与主锦标赛当前选择一致**（可改小以提速），总对局数 `values × strategies² × ceil(perPair/2)` 在 UI 实时提示并支持取消；扫描结果**不跨标签页持久化**（与 `savedShowdown` 不同，保持简单）。
- **D7 指标清单**：`METRICS` = Win %（`(wins+ties/2)/matches`）、Avg score（`avgScore`）、Margin（`avgMargin`）、± SD（`scoreStdDev`）、Tips（`avgTips`）、FLOWER pts（`breakdown.flowerBottom + breakdown.flowerOwned`）、RP（`avgRP`）、4+ tips（`p1Rate`）、7+ tips（`p2Rate`）——共 9 项；4+ 与 7+ 拆成两个独立指标。
- **D8 图表策略**：一张主折线图（指标可切换，每策略一条线）+ 可选「全部指标」小倍数网格。
- **D9 不改文档**：不新增或修改任何 `.md` 文档（未被要求）。
